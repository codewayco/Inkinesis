# Independent character preparation

The default pipeline connects our preparation code directly to See-through and pristine psd2live.

The implementation owns background and layer preparation, expression measurement and direct adapter code.

## What runs

1. The existing character drawer optionally generates the source image. Existing support/landmark inference evaluates that image.
2. `prepareCharacter.py neutralize` preserves source alpha, or estimates an edge-connected constant/smooth background. Enclosed white clothing remains foreground. Ambiguous complex backgrounds fail instead of silently erasing the drawing.
3. `localSeeThrough.py` invokes the original See-through model directly. Our manifest locks publisher revisions and weight hashes; the runner records its device/scheduler compatibility changes.
4. `prepareCharacter.py plan` derives feature regions from semantic alpha bounds, avoiding an additional vision-model planning request.
5. `editExpressions.ts` requests masked expression edits directly from the image API. Each cached edit is bound to the source pixels, mask, prompt and model. Missing independent eyes skip the eye edit and remain an explicit limitation.
6. `prepareCharacter.py prepare` cleans detached components conservatively, partitions unsplit limb artwork using anatomical landmarks, aligns edits against unchanged face pixels, matches the local skin collar, feathers feature boundaries and measures an open-mouth support. A PSD write/read round trip checks layer names, placement and pixels.
7. `DirectBust.kt`, launched by `prepareDirect.py`, calls pristine psd2live's public pipeline and exports its evaluated facial keyforms through our `PoseDump.kt`. The engine source is unmodified. Composite open-mouth opacity is explicitly zero at the closed endpoint.
8. Our combined builder adds the existing limb rig and coupled head motion. Optional scalar mouth-key compaction checks every original knot against a 0.025-pixel per-coordinate budget and a 1e-7 opacity budget; limb and coupled-head grids are unchanged. Bounds for independent additive mouth axes can accumulate.
9. Native INP validation and evidence rendering run as before. Optional Live2D export uses the same pristine engine and preserves the INP. Official Core validation is a separate command and acceptance check.

The mouth patch contains measured composite artwork, **not separately articulated teeth and tongue**. Depth maps are generated by See-through, but our current cleanup uses alpha/foreground connectivity rather than the former depth-assisted repaint policy. Semantic layer ordering is a declared anatomical order; unusual accessories and occlusion still need review. These differences must not be hidden in a claim of stage-for-stage equivalence.

## Installation

Follow the ordered installation steps in [README](../../README.md). `requirements.txt` installs preparation dependencies; `requirements-gpu.txt` belongs in the separate inference environment. See `.env.example` for every supported generation setting. Preflight checks local dependency paths and model sizes; inference additionally verifies source and weight hashes.

## Run and inspect

```sh
node --import tsx tools/imageToRig/pipeline.ts --check
node --import tsx tools/imageToRig/pipeline.ts --image /path/to/source.png --out outputs/my-run --live2d
node --import tsx tools/imageToRig/pipeline.ts --prompt "A front-facing adult character in a T-shirt and shorts" --out outputs/my-text-run --live2d
```

Generation sends the source/crops to the configured analysis and image providers and incurs API usage. See-through inference, preparation, rigging and geometry checks run locally. Use a new output directory.

The run report links `assets/character.psd` and `assets/preparation.json` in addition to the original decomposition, INP, evidence and optional Live2D package. Review the two sets of layers separately. A structural pass is not a visual approval; generated rigs remain `needs_review`.

For official Core validation, first install the optional SDK described in the Live2D runbook, then run:

```sh
node --import tsx reference/cubism/runCombinedCapture.ts /path/to/character.inp /path/to/live2d-export --near-keys
```

Absent eye controls are recorded as unsupported, not tested as a successful blink. This does not suppress missing authored controls or relax geometry/opacity tolerances.

## Runtime differences and limitations

Official Core snaps parameter values within 0.001 physical units of an authored key. Our native renderer interpolates continuously. The verifier reports strict source parity separately from a reference evaluated with Core's sampling convention. `passed_with_runtime_differences` means the latter passed the original tolerances; it does not mean exact cross-format equality.

Low-confidence anatomy, unusual clothing, absent eye layers, generated expression quality, and extreme head poses still need visual review. The publication examples are retained development outputs, not fresh outputs of each dependency installation. The release contains no private research evidence folders.
